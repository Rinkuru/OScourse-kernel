В данной лабораторной работе реализован планировщик системы реального времени. 

У каждого real-time (rt) процесса есть свой приоритет, задаваемый пользователем во время инициализации rt процесса. Данный приоритет не меняется в течение работы процесса.
Приоритеты имеют значения с 1 по 239 (ARINC 653) -- чем выше число, тем выше приоритет. 
Планировщик выбирает процесс с наивысшим приоритетом по принципу FIFO. Реализован массив очередей.
У каждого rt-процесса есть свой дедлайн, период, верхняя оценка на его выполнение.
При добавлении процесса оценивается нагруженность системы как sum(C_i / T_i), где C_i - верхняя оценка выполнения i-го процесса, T_i - период i-го процесса. При достижении суммы значения 1, мы перестаем принимать новые rt-процессы.
При нарушении какого-нибудь из процесса дедлайна, этот процесс становится обычным, и вместе с остальными обычными процессами выбирается по стратегии round-robin. Процесс может снова стать rt по запросу пользователя.

Для пользователя созданы 3 новых системных вызова, sys_rt_register, sys_rt_periodic_wait, sys_rt_unregister. Регистрация rt-процесса,
при завершении периода, и при отменен регистрации процесса как rt-процесс, соответсвенно
На каждом тике считает время выполнения rt-процессов, которые нужно обработать, и пробуждаем те процессы у кого должен начаться новый период.

В репозитории находятся тесты, которые демонстрируют работоспособность программы. Их вызвать можно с помощью команды "make test-scheduler"
